## 受控历史补发协议及实施门槛

1. 群管理员显式启用分享策略：最大回溯时间、最大条数、允许的消息类型。默认关闭。发送前重新核对发起人权限、接收人已加入、源房间、当前账号会话与策略版本。
2. 首版只选可解密的普通文本。拒绝已撤回、阅后即焚、转账、支付请求、附件及解密失败事件。以 canonical event ID 重新读取，不信任预览缓存。
3. 确认页列出接收人 MXID、消息数、最早/最晚时间及每条正文。先生成不可变批次 ID 和确认快照；内容、权限或会话变化使确认失效。
4. 仅把选中的明文重新加密到经过核对的接收人通道。不得导出或分享旧 Megolm 会话密钥；一个旧密钥可能开放未选中的历史。不得向整个群重新发送正文来假装定向补发。
5. 群内可见的审计事件记录批次、接收人、数量和时间范围，不含正文/密钥。跨房间发送与审计不具备事务原子性，须有持久状态：准备、审计声明、内容已发送、完成/待核对。超时不得自动重发，先按稳定事务 ID 对账；审计失败不能显示完整成功。
6. 自动化验收覆盖角色被撤销、成员离群、账号切换、撤回、策略变更、未知发送结果、断网重启及去重。再做接收方设备验收，证明只取得选中内容。后续实现使用独立仓库与持久日志，未复用普通转发来绕过这些边界。

## 真实实验与验收门槛

- 安全可靠性：3 台设备、20 人加密群、10,000 条混合消息；断网重连、撤销设备、30 次密钥恢复、前后台/终止状态推送、钱包桥接。丢失/重复=0，恢复=30/30，日志明文泄漏=0，撤销设备的新会话密钥=0，自动钱包执行=0。旧设备已持有的历史密钥不能远程抹除，不把这一点混同于新密钥撤销。
- 追赶体验：20–30 名同意参与的用户，随机交叉使用旧版/新版完成同一组决定、待办、本人相关消息任务。任务耗时中位数下降≥30%，未确认历史披露=0，分享范围理解率≥90%。记录样本、任务和失败结果，不能用单测代替。
- 本地行动：聚餐、会议、导航、闲聊四类授权样本；当前窄日历规则先测覆盖率和精确率，未支持类别明确记为不支持。精确率≥90%、内容外发=0、误执行=0、完成率提升≥20%。确认后的系统日历同步需纳入用户可见边界。

本轮未取得上述设备组合、受控账号组、服务端/推送日志及用户实验样本，因此不执行生产聊天、密钥撤销或资金交易。未测量数据保留 null；不以 README、测试夹具或 TestFlight 上传补齐。
